问题篓子 · 机器人篇 № 005

人形机器人会乘电梯吗？

它能爬 33 级台阶、能翻越等身高的障碍。但它进不了一部正在关门的电梯——目前唯一那篇人形电梯论文里，门是研究者用手按住的。

2026-07-25 · 覆盖 ICRA / IROS / Humanoids / Frontiers / 产业 API / ISO 标准 · 三条路线十六年 · 人形唯一一篇
结论先行：
  1. 产业界已经大规模解决了——用绕开物理操作的方式。Otis 的 Integrated Dispatch 云 API 已对接 60 多家机器人公司，KONE 的 Elevator Call API 同理。在这条路上，电梯不再是"被操作的物体"，而是一个可以调用的服务：机器人发个请求，梯自己来、门自己开。
  2. 真用胳膊按物理按钮、并且做到规模化的，全世界基本只有一家。Diligent Robotics 的 Moxi——截至 2024 年 11 月公布的数字是 11 万次以上自主乘梯、月均 2 万次以上，约 100 台机器人分布在 20 个站点。但它是轮式底盘 + 一条手臂的类人形，不是双足人形，且靠人在环远程监督兜底。
  3. 人形 + 学习方法 = 空白。唯一一篇人形电梯论文（KIT 的 ARMAR-7，2025 年 9 月）走的是经典规划 + 感知，不是学习。它的真机结果非常诚实：按钮检测与位姿估计失败率不到 20%，按压本身"大约一半的情况能成"；论文明确写着——为避免碰撞，实验中电梯门是研究者手动按住的。没有任何一篇 learning-based 的人形乘电梯工作。
  4. 它比开门（№003）难在完全不同的地方。开门难在力与铰接；电梯难在时间、社交与不可观测：门大约 6 秒就关；轿厢里有人，站位互相挤占；按钮按没按亮，机器人自己看不出来。

KIT 高性能人形技术实验室的 ARMAR-7 是欧洲最先进的家用人形之一：双臂各 8 自由度、力矩控制、欠驱动五指手、立体视觉头、全向移动底盘。2025 年，这个组发表了迄今唯一一篇人形机器人乘电梯的论文。在结论的"局限性"一节里，作者写下了这样一句：

"为避免碰撞，我们手动按住电梯门，因为我们的机器人目前缺乏安全进入电梯的策略。"
—— Arlt et al., A Humanoid Robot Asks Humans for Help to Navigate Elevators, 2025

这句话几乎是本期的全部答案。人形机器人可以爬 33 级台阶（见 №004）、可以在广州塔冲刺、可以翻越等身高的障碍——但它进不了一部正在关门的电梯。

先把"乘电梯"拆开

日常里三秒钟不过脑子的动作，展开来是一条六段的长时序任务链，每一段的失败模式都不一样：

阶段机器人要做什么硬约束
① 叫梯找到外呼面板、判断上/下、按下按钮直径约 2 cm，末端定位精度要求高
② 等待判断哪一部梯到了、门开了没、还有没有空间多梯厅歧义；门状态需实时判断
③ 进入在门开到门关之间进去，且先让人出来硬实时：门约 6 秒；社交约束
④ 按层在轿厢内找到内呼面板、够到目标楼层、确认按亮空间狭小、面板可能被人挡；按亮与否不可观测
⑤ 乘行判断到了几层无 GPS、里程计失效、视觉全是同一面墙
⑥ 出梯在门再次关闭前出去，且不撞人又一次硬实时 + 社交

和开门对照着看，差别就清楚了。开门的难点是物理的：门有几十公斤、闭门器一直往回顶、力控刚度高了触发急停低了推不动。电梯的难点是时序与信息的：力几乎可以忽略（按一个按钮只需几牛顿），但你只有 6 秒钟、旁边站着三个陌生人、而且你不知道自己刚才那一下到底按上没有。

这也解释了为什么"电梯"没有像"开门"那样长成一个热门的 RL 任务：它的困难不在那个可以被奖励函数描述的部分。

路线一：把电梯变成 API（工业界赢的那条）

面对上面那张表，产业界的回答干净利落：这六段里有五段是可以被删掉的。

Otis 推出的 Integrated Dispatch 是一套云端或本地部署的 API，专门用于把服务机器人接进 Otis 电梯群控——机器人不再需要看见按钮、够到按钮、判断门开没开，它只需要发一个请求。Otis 公开表示已与 60 多家机器人公司对接，并提供在线仿真环境让开发者在部署前把 API 联调完。KONE 的 Elevator Call API 走同一条路，被德国的 Robotise 用在酒店送物机器人 Jeeves 上。Relay Robotics 则自建了一层云集成，把 Otis、Schindler、TK、三菱、KONE 各家协议统一在自己的抽象层之下。

这条路线正在被标准化固化下来：ISO 正在推进的 ISO 26159 系列（机器人应用的基础设施）明确把电梯列为"机器人应用的基础设施要素"，规定机器人与基础设施之间该交换什么消息、按什么流程操作。也就是说——电梯正在被官方重新定义成机器人可以调用的一个接口，而不是机器人要去操作的一个物体。

对于本期问题，这条路线的意义是双重的。它证明了"机器人跨楼层"这个业务需求已经被彻底解决；同时它也解释了为什么"机器人按电梯按钮"这个科研问题热不起来：在任何愿意花钱改造楼宇的场景里，物理操作是一个自己给自己找的麻烦。

路线二：把人变成 API

第二条捷径来自卡内基梅隆的 Manuela Veloso 组。他们的 CoBot 系列提出了共生自主（symbiotic autonomy）这个范式：机器人清楚地知道自己能力的边界，遇到做不到的事——按电梯按钮、开门、把东西放上托盘——就主动请路过的人帮忙。

这在工程上非常聪明：CoBot 干脆没装手臂，省下的成本与复杂度全部投入导航与调度。但代价同样明确，而且被后来者反复引用为反面案例：没人的时候机器人会被困住。KIT 那篇人形论文的对比实验里，纯求助基线在"周围无人"的两个场景中成功率直接是 0%。

路线三：真的去按那个按钮

学界这条线走了十六年，而且走出了一个值得玩味的形状。

2010：斯坦福，86.2%

起点是 ICRA 2010，作者是 Ellen Klingbeil、Blake Carpenter、Olga Russakovsky 和 Andrew Ng。他们瞄准的问题非常具体：让机器人操作一部它从没见过的电梯。当时已有的机器人系统要么靠人帮忙，要么靠给电梯加装红外收发器——论文里那句吐槽今天读来依然成立：给所有电梯都加装接收器成本高、耗时长，而且如果机器人要在大量不同建筑里跑，根本不现实。

技术上他们用滑动窗口检测 + OCR 找按钮和标签，再用机器学习利用上下文线索——按钮排成网格、楼层按顺序排列——用期望最大化把按钮拟合到网格上以恢复漏检，用隐马尔可夫模型纠正 OCR 认错的标签。在 150 张来自 60 多部不同电梯的照片上，正确定位并标注了 86.2% 的按钮；真机实验里，在 3 部没见过的电梯上做 14 次尝试，14 次全部正确定位、13 次正确按下。

2021：港中大，把数据集做出来

十年后，香港中文大学的 Delong Zhu 等人补上了这个方向缺的那块基础设施：第一个大规模公开的电梯面板数据集——3718 张面板图像、35100 个按钮标注，配套的 OCR-RCNN 框架把检测与字符识别串起来（检测 F1 0.94 / 1.00 / 1.00，字符识别准确率 79.6% / 96.5% / 96.4%）。他们对现状的判断在论文里写得很直白：能跨楼层导航的机器人很受关注，但现有机器人要么依赖人的协助、要么依赖电梯改造，完全自主的跨楼层导航尚不可得。

这套东西开源了，至今仍是这个方向唯一像样的公共资产。

2023–2025：伊尔梅瑙，把整条链路跑通

真正把六段全部接起来跑到底的是德国伊尔梅瑙工业大学（TU Ilmenau）神经信息学与认知机器人组。他们先在 IROS 2023 交出感知部分，2025 年在 Frontiers in Robotics and AI 给出完整系统与迄今最详尽的一份现场数据。

平台是 SCITOS G5 差速轮式底盘 + Kinova Gen II 七自由度臂，两台 SICK 激光雷达、云台上的 Azure Kinect RGB-D。按钮用 Faster-RCNN 检测 16 类，配深度数据算出三维位置与表面法向，与预先建好的面板地图匹配；按压动作是规划一段接近运动，接一段直线推压、以力反馈事件终止。进梯前用激光雷达分析门宽判断轿厢状态，空了才进，并主动给等候的乘客让路、用语音告知自己需要空间——这是社交导航在真实场景里少见的完整实现。

但要读懂它，必须同时读它的失败分析——那才是真正的信息：定位精度不足（蒙特卡洛定位约 7 cm 的精度不足以直接够到按钮和门把手），大空间里全局定位出错会导致机器人陷入死循环（办公楼里发生两次，非人工干预无法恢复）；电梯轿厢的反光表面让深度感知出错；差速底盘无法横移，限制了开门动作序列；电梯意外停靠时机器人无法判断自己在几层。

2025：KIT，唯一的人形

最后是那篇人形论文：KIT 的 Niklas Arlt、Fabian Reister、Christian Dreher 与 Tamim Asfour，题目直白得像一句坦白——《一台人形机器人请求人类帮它乘电梯》。

它的核心不是"怎么按按钮"，而是什么时候别自己按。系统实时评估环境约束，判断自主操作是否可行，不可行就切换到求助模式。判据用的是可供性空间（affordance space）这个概念：按按钮这个动作需要机器人站在面板前那一小块地上，人一站过去，这块地就没了，动作在几何上就不可行了——此时与其硬挤，不如开口。门状态则靠激光雷达判断，即便有人正在进出也能稳定识别。

但真机部分才是本期最该被读到的段落，因为它把人形的实际水位摊开了：按钮检测与位姿估计失败率不到 20%（失败时机器人手指会朝错误方向动）；按压本身大约一半的情况能成，且严重依赖标定；机器人有时无法及时判断自己已经到达目标，导致反复重算、在多个目标间振荡；进梯通常能在门开后 6 秒内完成，但偶有慢的时候就进不去、门在面前关上。而最关键的两条局限写在结论里：电梯门由人手动按住，因为机器人还没有安全进入的策略；以及按压失败需要人介入，因为机器人无法验证按钮是否被激活。

宏观观察

其一，唯一规模化的物理方案，恰恰不是人形。Moxi 十一万次乘梯说明"用机械臂按真实按钮"在工程上完全可行——但它的形态选择极其克制：轮式底盘（不会摔、不用管平衡、底盘稳定意味着手臂的基座是刚性的）、一条手臂（够用了）、类人形上身（为了在医院里显得友好），加上人在环远程监督兜底。这是一个关于形态经济学的结论：在电梯这个任务上，双足带来的全部是成本——它让基座变成一个随时可能晃动的浮动平台，却没换来任何电梯场景独有的收益。楼梯需要双足，电梯不需要。

其二，学界十六年只推进了感知那一段。2010 年斯坦福在没见过的电梯上按对 13/14；2021 年港中大把检测 F1 做到 0.94；2025 年伊尔梅瑙的现场乘梯成功率 93.2%。看起来一路向上——但注意 2025 年 KIT 的人形上，"按压本身大约一半成功"。"看见按钮"这件事进步巨大，"把手指按到按钮上"这件事在人形上反而退步了，因为平台从固定基座的轮式臂换成了浮动基座的人形。感知的进步被本体的退步吃掉了。

其三，电梯把 loco-manipulation 的所有难点压进了 30 秒。开门是一个准静态的力学问题，你可以慢慢来；电梯不行。它同时要求：厘米级的末端定位（按钮直径 2 cm，而伊尔梅瑙报告的定位精度是 7 cm）、动态障碍规避（人）、硬实时（门 6 秒）、状态不可观测（按亮没有）、以及无法量化的社交合规。任何一项单独看都有人在做，六项同时满足的公开工作目前是零。

其四，标准化正在从两端同时收口。ISO 26159 系列把电梯写进"机器人应用的基础设施"，Otis 和 KONE 把 API 铺到 60 多家机器人公司。这意味着新建与改造的商业楼宇里，物理操作电梯的需求会持续萎缩。物理方案真正不可替代的战场只剩下：老旧楼宇、住宅、无法改造的既有设施、以及基础设施失效时（断电、网络中断、灾害）。这和 №003 里"工业界系统性绕开通行门"的结论是同一个逻辑的第二次出现，而且这次绕得更彻底——门至少还得有人去推，电梯连推都不用了。

其五，学术评测体系本身在回避这个问题。视觉语言导航与具身导航的主流基准几乎全部是单层平面环境，"上三楼"这种指令根本不在评测范围内。一个能力如果不在任何 benchmark 里，就不会有人为它优化。这可能才是"没有 learning-based 人形乘电梯工作"最根本的原因——不是太难，是没有跑分。

瓶颈与开放问题

  1. 定位精度差一个数量级。电梯按钮直径约 2 cm，而伊尔梅瑙报告的机器人全局定位精度约 7 cm——这中间的差距必须靠视觉伺服在末端闭环补掉，而 KIT 的结果说明人形上这一环还不稳（按压约一半成功、强依赖标定）。人形比轮式更难的地方在于：基座本身在晃，手眼标定不是一次性的事。
  2. 硬实时约束下的进出梯，是人形完全没解决的一环。门约 6 秒，而人形必须在移动中保持平衡、不能急停急转。KIT 的应对是让人按住门——这不是敷衍，是承认现有的双足运动控制在这个时间窗内没有安全余量。论文自己给出的思路很有启发：伸一条胳膊挡在门口，快关上时再迅速收回。这恰恰是人形相对轮式的结构优势（两条胳膊：一条挡门、一条按键），但至今没人实现。
  3. 按压缺少闭环验证。机器人按完不知道按亮了没有——这是个纯粹的感知问题（按钮点亮的视觉/电流反馈），却因为没人做而成了整条链路里最脆的一环：失败必须人介入。这大概是本期投入产出比最高的一个可做点。
  4. 轿厢是感知的敌对环境。不锈钢、镜面、玻璃——伊尔梅瑙明确报告反光表面导致深度感知出错。而人形往往比轮式机器人更依赖深度相机。
  5. 楼层识别没有可靠手段。电梯里没有 GPS、里程计失效、视觉全是同一面墙。伊尔梅瑙的系统在电梯意外停靠时无法判断自己在几层。气压计是个显而易见的候选，但公开文献里几乎没人认真讨论。
  6. 社交约束无法写进奖励函数。"让人先出""不挤进已满的轿厢""不挡在门口"——这些没有客观的成功/失败信号，评价依赖人的主观感受。这正是社交导航领域至今缺乏公认定量基准的原因，而电梯是它最浓缩的场景。
  7. 没有仿真资产，也没有基准。没有一个公开的电梯仿真环境包含：会自动关的门、可按的按钮面板、会走动的乘客、多楼层状态机。开门至少还有 DoorGym；电梯连这个都没有。而这恰恰是 learning-based 方法能不能进场的前提——没有仿真器，就没有 sim2real，就没有 RL。这可能是这个方向真正的第一块砖。

如果要在 G1 上做电梯

本期的证据指向一个相当明确的判断：别把"乘电梯"当成一个整体任务去啃，它现在还不是一个可训练的问题。真正可做、且缺口最明确的是三个子问题，都比整条链路小得多：

① 一条胳膊挡门 + 一条胳膊按键这是人形对轮式的唯一结构优势，KIT 点名了它却没做。它是一个干净的双臂协调 + 时序约束问题，可以在仿真里构造（一扇会自动关的门 + 一个可按面板），G1 的双臂完全够用。做出来就是真空里的第一篇。
② 按压的闭环验证按钮点亮的视觉检测 + 失败重试策略。技术上不难，但它是当前所有系统里唯一必须人介入的环节——补上它，系统的自主度会有质变。
③ 电梯仿真资产在 Isaac Lab 里建一个参数化电梯场景（门开闭时序、面板布局随机化、轿厢反光材质、可配置乘客）并开源。参照 DoorGym 之于开门的位置——这是缺的地基，也同时是 ①② 的训练场。

而整条链路建议先按伊尔梅瑙的方式工程化实现（预先建图 + 行为架构 + 力反馈按压），而不是端到端学习——他们 88–93% 的乘梯成功率证明了这条路走得通，而 KIT 证明了人形版本的短板集中在运动控制与标定，不在决策。

最后一句实话，也是把 №004 和本期放在一起才看得清的：楼梯比电梯好走。同一栋楼里，让 G1 爬上三楼这件事，学术上有清晰的方法谱系、有可复现的开源生态、有明确的性能刻度；而让它坐电梯上三楼，你会发现自己站在一片没有仿真器、没有基准、没有前作的空地上。这既是坏消息也是好消息——取决于你想做工程还是想做贡献。
