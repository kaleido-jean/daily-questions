人形机器人按得下电梯按钮吗？

一份逐段查过的可复现代码清单。八年前这件事被解决过一次，成功率 95.7%——代价是先由人把每个按钮标注一遍。

2026-07-28 · 覆盖 ICRA / IROS / HRI / arXiv / GitHub 65 个仓库逐个硬核实 · 八段链路逐段查代码 · 含可复现性分级
结论先行：
  1. 这件事在 2018 年被解决过一次。杜克大学的 SwitchIt 在真实办公楼与住宅里操作了 234 个按钮与开关，成功 224 个（95.7%），感知定位误差 < 2 mm。代价是：每个按钮先由人用平板 + 二维码标注一遍。八年后的人形把"人"拿掉了，也把成功率一起拿掉了——唯一那篇人形电梯论文（KIT ARMAR-7）真机按压约一半成功。
  2. 八段链路里只有一段是成熟的。②识别按钮成熟；①④⑥有大量相邻代码但没有一个是为按钮写的；③⑤⑦⑧四段接近空白。
  3. 但"空白"没那么空。两件没被任何综述收录的东西：一个 0 star 的韩国学生仓库把③⑤⑥⑦四段各写了一遍；人形按按钮的公开数据也不是零——RoboMIND 天工人形有 527 条 / 269,791 帧，而它的下载量只有 36。
  4. 真正的瓶颈不是精度，是力和验证。各方法按压成功率都落在 45–55% 且统计上不可区分，但峰值压力中位数——人类 3.41 N，机器人策略 5.87–9.37 N。机器人不是按不到，是按得太重，而且按完不知道按亮没有。
  5. 第一个该做的任务不是轿厢面板，是电梯外呼板：只有 2 个目标、固定在墙上 1.0–1.2 m、不用进轿厢、不受 6 秒关门倒计时约束。所有公开数据集里都带 call/up/down 类，只是从没人把它当成独立问题做过。
⚠️ 一个绕不开的前提：本期几乎所有可用的仿真栈（Isaac Sim / Isaac Lab / VIRAL / unitree_sim_isaaclab）都要求 Ubuntu 22.04 + NVIDIA GPU。macOS 上一个都跑不了，得先备一台 Linux + N 卡机器。唯一的例外是 MuJoCo 系（Meta-World、mjlab、RoboCasa），Mac 上能跑。

2018 年那次"已解决"

先看一眼这个问题被认真做完过是什么样子。

2018 年 ICRA，杜克大学电气与计算机工程系的 Fan Wang、Gerry Chen 和 Kris Hauser 发表了 SwitchIt——一个小到能装在移动机器人上的三自由度球形装置，带一个 RGB-D 相机。他们做的第一件事不是训模型，而是去数按钮：系统调查了办公室与住宅里 600 多个按钮与开关，按"对机器人操作而言相关的物理属性"——行程、尺寸、形状、操作力——把它们归成 6 类。

这个分类学是整篇论文最被低估的贡献。它意味着"按按钮"不是一个任务，而是六个不同的任务：按压式、拨动式、旋钮、滑动、摇臂各有各的力学。

第二件事是一个纯机械的洞察：他们设计了一个顺应性扇贝形（scalloped）指尖。在同样的定位误差下，这个指尖的操作重复率是 99%，而普通圆柱形指尖只有 89%。换句话说——指尖的形状，比控制算法更能吃掉定位误差。

档案 · SwitchIt（Robot Button Pressing In Human Environments）
团队Fan Wang、Gerry Chen、Kris Hauser，Duke University 电气与计算机工程系（NSF CAREER #1253553） 方法三自由度球形装置 + RGB-D；人工二维码标定阶段 → 自动识别 / 按压 / 状态检测；顺应性扇贝形指尖 数据系统调查 600+ 个真实按钮与开关，按物理属性归为 6 类（行程 / 尺寸 / 形状 / 操作力） 基准真实办公楼 + 住宅 234 个开关成功 224 个 = 95.7%；感知定位误差 < 2 mm；拨动开关状态识别 100%；扇贝尖重复率 99% vs 圆柱尖 89% 前提需人工用平板 + 二维码预先标注每个按钮，非零样本 开源未见代码 发表ICRA 2018 链接论文 PDF（挂在 Hauser 后来所在的 UIUC 站点）

八年过去，这篇论文在近年的电梯按钮工作里几乎不被引用。而它恰恰回答了后来所有人都在绕的那个问题：按按钮的难点从来不在"按"，在于知道按哪一个、以及按到没有。

②是唯一的好消息，但它的地基在塌。最省事的起点是 isharadilshanra/YOLOv10-Elevator-Button-Detection——2019 张图、368 个类别的数据集和训练好的 17 MB 权重都直接躺在仓库里，pip install ultralytics 就能跑。但别相信它的精度：368 类 ÷ 1412 张训练图 ≈ 每类 3.8 张，长尾里还有 text_oepn（拼错的单词自成一类）这种几乎必然是单样本的类。更麻烦的是港中大那份权威数据集的下载链接在三个仓库的 README 里实测全部 404，想重训都没有源头。这也是为什么开放词汇检测这条"根本不用训"的路线值得认真评估——虽然它在小目标、反光面板上的召回还没人系统验过。

④是最拥挤也最容易被误判的一段。人形全身控制的仓库多到数不过来（HOVER、ASAP、TWIST、FALCON、OpenHomie……），很容易让人以为"够取"已经解决了。但逐个查下去：unitree_rl_lab 的任务只有 locomotion 与 mimic；unitree_sim_isaaclab 的 15 个任务全是抓/放/堆/搬，README 全文 button 与 press 命中 0；HOVER 形态最像但全仓零 G1 文件；FALCON 虽有末端指令，却只绑手柄且左右手镜像联动，根本没法单手指向一个按钮。没有一个仓库提供"把末端送到指定三维点"的人形 reach 任务。

真正能用的只有一件：Isaac Lab 官方的 Isaac-PickPlace-FixedBaseUpperBodyIK-G1-Abs-v0，它的 pink_controller_cfg.py 用 Pink IK 给 G1 左右腕各配了独立的 LocalFrameTask。但要泼一盆冷水：它控的目标是腕部相对骨盆的位姿，而按按钮要控的是指尖，中间还隔着指尖坐标系定义、手指构型和压入时的柔顺性。

⑧是真正的零。按偏了、力度不够、手指挡住了指示灯——这些在真实电梯里天天发生，而没有任何一个开源仓库为按钮任务写过"退回去重来"的逻辑。

资产这一层还有一个被普遍忽略的答案：PartNet-Mobility（SAPIEN）里有带运动学标注的 URDF——Switch 类 70 个模型 / 195 个可动部件，Remote 类 49 个模型 / 1490 个可动部件（遥控器本身就是一整片 prismatic 按钮阵列）。Isaac Sim 自带 URDF importer，这是把"能按下去的按钮几何"搬进你本机栈成本最低的一条路。

自建一个 G1 按钮任务的三件设计输入已经齐了：PartNet-Mobility 的可按资产 + Meta-World 的行程判据 + RoboCasa 的撤手逻辑。三件都可下载、可读源码、都不需要真机。

那个 0 star 的仓库

本期最意外的发现来自对抗性查漏。

uihyeong/elevator-button-robot（MIT，最后提交 2026-07-10，0 star）——一个韩国学生做的自动配送机器人项目，硬件是 OpenMANIPULATOR-X 四轴臂 + RealSense D435 + Scout Mini 底盘，跟人形毫无关系。但它的 85 个文件里有这样一条节点链：

nodes/simulation/isaac_sim_yolo_depth.py ← ③ 2D 框 + 深度 nodes/simulation/isaac_sim_yolo_tf.py ← ③ 转成 TF 坐标 nodes/simulation/isaac_sim_yolo_moveit.py ← ④ 接 MoveIt2 ros2_packages/isaac_moveit_bridge/bridge.py ← Isaac Sim ↔ ROS2 桥 nodes/real_robot/aruco_servoing.py ← ⑤ 视觉伺服 nodes/real_robot/contact_detector_svm.py ← ⑥ 接触判定（+ svm_collision_model.pkl） nodes/real_robot/test_button_lit.py ← ⑦ 按亮检测 nodes/real_robot/test_gemini_detection.py ← 用 VLM 做检测的先例

这恰好是上面那张表里标"空白"的③⑤⑥⑦四段的一份可读实现，而且接触分类器是拿 FSR 实测数据训出来的。

它不是给你跑的——四轴定臂、轮式底盘、韩文注释，跟 G1 差着十万八千里。它是给你抄结构的：一个人独立把这条链路走通一遍，需要哪些节点、每个节点的输入输出是什么，这份文件清单就是答案。

它 0 star 这件事本身值得停一下：这个方向的实践知识散落在没人看见的学生项目里，而不在论文和高星仓库里。

力：机器人按得比人重一倍

根特大学（Ghent University—imec，IDLab-AIRO）2026 年的《You're Pushing My Buttons》把一个被所有人跳过的问题摆上台面：按下去了，但按得对不对？

他们的做法很聪明——在指尖装一个麦克风，训练时用接触音频当额外监督信号，部署时不依赖它（论文管这叫 training-time instrumentation）。测试台是一个装了 Bota F/T 力传感器的机械臂，从随机起始位置沿随机轨迹去按同一个按钮。这是接触丰富操作里一个很典型的处理思路。

结果是本期最锋利的一组数字：

方法峰值竖直力中位数
人类专家演示3.41 N
Deep Fusion（embeddings）5.87 N
Deep Fusion（classifier）5.95 N
通用音频编码器基线6.98 N
Soft Sensor9.37 N
 而各方法的按压成功率全部落在 45–55% 的窄区间内、统计上不可区分。数据：arXiv:2604.05954。

这两行合起来说明：成功率这个指标在按按钮任务上几乎没有分辨力，真正区分好坏的是力。最好的机器人策略也比人重了将近一倍，最差的接近三倍。对电梯按钮这种带 2–3 mm 弹簧行程的塑料件，这意味着长期作业下的磨损甚至损坏——而没有任何一篇人形工作报告过自己的按压力。

最后几厘米：唯一一篇正面做人形的

⑤这一段在人形上是空的，但有一篇工作正对着它。

arXiv:2503.04862 做的是"把螺丝刀尖对进螺丝槽"——比按钮更苛刻的对准任务。它的关键设计是融合头部与躯干两个相机：头部相机看全局但视差小，躯干相机离作业点近但视野窄，用一个 Distance Estimation Transformer 直接回归两者之间的 XYZ 距离，再选择用哪个感知头。

这正是浮动基座人形该有的形态——不去追求一次手眼标定到位（那在会晃的基座上做不到），而是让视觉伺服持续闭环把误差吃掉。

档案 · High-Precision Transformer-Based Visual Servoing for Humanoid Robots
团队一作 Jialong Xue；Wei Gao、Yu Wang、Chao Ji、Dongdong Zhao、Shi Yan、Shiwu Zhang 方法头部相机 + 躯干相机图像融合 → Distance Estimation Transformer 回归 XYZ 距离 → 感知头选择 → 视觉伺服闭环 平台人形（2-DoF 头 + 7-DoF 臂 + 6-DoF 手）；任务为螺丝刀尖对准螺丝槽 开源未见代码（Comments 只给了视频链接） 发表预印本，未见录用信息 链接arXiv:2503.04862 · alphaXiv（无项目页）

补上工具链的坐标：经典方案是 ViSP（lagadic/visp，900 star，仍在维护，但 GPL-2.0，商用要留意传染性），它输出的是相机速度旋量；要接到 G1 上，"相机速度 → 末端速度 → 关节指令"以及浮动基座雅可比都得自己补，官方教程只覆盖 Franka。IK 这一层还漏掉了两件主流工具：cuRobo（NVlabs，Apache-2.0，Isaac Sim 原生、GPU 并行 IK + 无碰撞轨迹）与 MoveIt 2 的 moveit_servo（实时笛卡尔伺服，正是"给末端一个速度指令"这个接口）。

宏观观察

其一，这个方向的注意力分布严重畸形。openpi 有 12989 star、Isaac-GR00T 有 7683，而电梯按钮感知这条线上唯二的公共资产是 ocr-rcnn-v2（56 star）和 elevator_button_recognition（42 star）。arXiv 全文检索 "elevator button" 一共只有 4 篇，2021 年那篇港中大数据集之后再无实质新工作。一个每天被几十亿人执行的动作，在机器人学里的研究强度约等于零。

其二，八年来这个领域一直在把"按"这个动作外包出去，只是外包对象在变。2018 年 SwitchIt 外包给布置环境的人（先贴二维码）；CoBot 外包给路过的陌生人；2025 年 KIT ARMAR-7 外包给挡路的人（可供性空间被占就开口求助）；2026 年 HRI 那篇导盲四足更直接——机器人负责精确定位，按钮由它服务的视障用户去按。四代人换了四个外包对象，唯独没换的是：没有一台机器人被要求自己独立完成这件事。

其三，指标选错了，所以进步无从衡量。根特的数据说明成功率在这个任务上分辨力接近于零（所有方法 45–55%），真正有区分度的是力。而现有的仿真判据要么判距离（Meta-World，阈值 2 cm 比真实行程大一个量级），要么判接触+撤手（RoboCasa，不保证走完行程），没有一个判"施加了多大力、走完了多少行程"。一个领域如果连正确的指标都还没有，"进展"这个词本身就可疑。

其四，实践知识沉在看不见的地方。本期最有用的一份工程参考是 0 star 的学生项目，最完整的人形按按钮数据集下载量是 36，而最该被引用的 2018 年 SwitchIt 在近年工作里几乎不被提及。与此同时，五个 200 到 500 star 的仓库 clone 下来是空的。star 数与可用性在这个方向上几乎不相关。

其五，工业界照旧绕开。这一点在 №005 已经说过——Otis / KONE 的云 API 把电梯变成可调用的服务。补充一个当时漏掉的开源坐标：open-rmf/lift_adapter_template 是官方的电梯适配器模板，而 open-rmf/rmf_simulation 里真的有电梯仿真。所以准确的表述不是"没有电梯仿真"，而是——有可被呼叫的电梯，没有面板按钮能被机械手按下去的电梯。

瓶颈与开放问题

  1. 力，而不是精度。机器人按压峰值力是人类的 1.7–2.7 倍，且没有任何人形工作报告过这个数字。路径：把力写进奖励与成功判据（而不是只判距离/接触）；借鉴 SwitchIt 的顺应性指尖——机械柔顺比控制柔顺便宜得多、也可靠得多。
  2. 按亮的闭环验证。全网只有三个粗糙实现，最知名的那个作者自己留了 # TBD: press detection needs to be optimized，代码里还有一句取反补丁。这是整条链路里投入产出比最高的一个可做点：一个按钮点亮的视觉分类器技术上不难，但它是当前唯一必须人介入的环节。
  3. 浮动基座的手眼标定。定臂标一次能用很久；人形站立时基座在晃，标定误差随姿态漂移。现有三个开源标定工具没有一个对得上——要么 eye-to-hand 构型不符，要么要求机器人发 ROS 2 tf 而 Isaac Lab 栈默认不跑 ROS。
  4. 没有一个人形 reach 任务。这听起来不可思议，但确实是本期查证的结论：Isaac Lab 的 Isaac-Reach-* 只有定臂，所有 G1 全身控制仓库提供的是运动跟踪与行走，没有"把指尖送到指定三维点并保持"。而这是按按钮最基础的前置能力。
  5. 判据与资产的错配。电梯按钮弹簧行程 2–3 mm，而 Meta-World 的成功阈值是 2 cm。要做对，得自己用 PartNet-Mobility 的 prismatic 按钮资产 + 毫米级行程阈值造任务。
  6. 失败重试完全空白，而这恰恰是真实场景的刚需（按偏了、力度不够、手指挡住指示灯）。
  7. 场景假设太窄。全部工作只谈轿厢内面板，而触摸屏电梯、刷卡梯、盲文按钮会让"纯视觉 + 按压"这条路线整个失效。

给你的 G1 项目：从外呼板开始的最小路径

先解决基础设施：Isaac 系全栈要 Ubuntu + NVIDIA GPU。在那台机器到位之前，可做的是 Meta-World / mjlab / RoboCasa（MuJoCo 系，Mac 能跑）。

然后，第一个任务选电梯外呼板，不要选轿厢面板。理由很硬：

轿厢内面板电梯外呼板
目标数量20–40 个，密集排布2 个（上 / 下）
位置轿厢内壁，需先进梯固定在墙上，1.0–1.2 m
时间约束受 6 秒关门倒计时无
环境镜面不锈钢，深度感知失效一般为平面墙
数据有（368 类里占多数）有（call/up/down 类都在）
 外呼板同时也是逻辑上的第一步——不按它，机器人根本进不了轿厢。而它从来没被当成一个独立问题做过。
① 造任务PartNet-Mobility 的 Switch/Remote URDF 经 Isaac Sim URDF importer 转 USD，照 humanoid-bench 的 door.py 写一个 button.py；判据用毫米级行程阈值 + RoboCasa 的撤手逻辑，外加一个峰值力上限——根特的数据说明这一项必须进奖励。
② 够取从 Isaac Lab 的 Isaac-PickPlace-FixedBaseUpperBodyIK-G1-Abs-v0 + pink_controller_cfg.py 起步，把控制目标从腕部改到指尖。
③ 感知先用特权状态绕开视觉，把力控做对；之后接 isharadilshanra 的 YOLOv10 权重，或直接试 GroundingDINO 零样本。
④ 最后几厘米抄 uihyeong 的节点链结构（yolo_depth → yolo_tf → IK → contact_detector → test_button_lit），控制律参考 arXiv:2503.04862 的双相机融合。
⑤ sim2realNVlabs/GR00T-VisualSim2Real 是同构度最高的模板（Isaac Lab + G1 + 视觉 + 教师-学生 + ONNX 导出）。
⑥ 真机兜底xr_teleoperate → unitree_IL_lerobot → lerobot 是唯一一条你不用等任何人开源、自己就能从零造出"G1 按按钮"数据并训出策略的完整通路。

novelty 在哪："人形自主按下电梯外呼板并完成按压验证"目前是文献空白——没有人形 reach 任务、没有毫米级行程判据的按钮资产、没有按亮闭环验证、没有失败重试。这四件里任何一件单独做出来并开源，都填的是真空。而它与开门（№003）共享同一块地基：末端受力时的全身平衡；与楼梯（№004）合起来，就是"让 G1 自己上三楼"的完整拼图。
